## Запуск учебного сайта

Подготовка рассчитана на Debian 13 в этой облачной машине. Установка выполняется
без root в `/workspace/.uitu-tools`, подписи пакетов и TLS проверяются. В других
системах можно установить Apache, PHP с PDO MySQL и MariaDB штатным пакетным
менеджером и адаптировать пути конфигурации.

```bash
cd /workspace/UITU
bash scripts/setup.sh
bash scripts/start.sh
```

Apache слушает порт 8080 на loopback; PHP FastCGI — 9000 на loopback. База доступна
только через Unix-сокет `.runtime/mysql.sock`. Скрипт проверяет инициализацию
каталога и ответ session API. Повторный запуск сохраняет данные. Остановка:

```bash
bash scripts/stop.sh
```

В учебной изолированной машине база использует локальную учётную запись без
пароля. Это конфигурация демонстрации; перед внешним развёртыванием требуются TLS,
защищённая конфигурация БД, резервное копирование и эксплуатационные ограничения.

Первого администратора создайте с собственным паролем через стандартный ввод:

```bash
read -rs -p 'Пароль администратора (не менее 10 символов): ' UITU_NEW_PASSWORD
printf '%s' "$UITU_NEW_PASSWORD" | bash scripts/php.sh app/create-user.php \
  admin@example.test 'Администратор системы' admin
unset UITU_NEW_PASSWORD
```

Сотрудник регистрируется через веб-форму. Администратор назначает права поддержки
в разделе «Пользователи». Демонстрационные учётные записи браузерного теста имеют
случайный локальный пароль, который не включён в Git и отчёты.

## Проверки

```bash
bash scripts/php.sh tests/unit.php
python tests/verify.py
python tests/browser.py
```

Первые 10 тестов проверяют чистые правила приоритетов, переходы и расчёт времени.
Следующие 20 проверяют модули через HTTP с реальной БД и изолированными тестовыми
данными, удаляемыми после запуска. Браузер выполняет 13 проверок интерфейса.
Их результаты и реальные снимки сохранены в `evidence`.
Сценарий браузера создаёт демонстрационные обращения; выполняйте его в учебной БД.
Для браузерного теста нужны Python-зависимости из `requirements-docs.txt` и Chromium.

SLA: P1 — 15 мин / 4 ч, P2 — 30 мин / 8 ч, P3 — 2 ч / 24 ч,
P4 — 4 ч / 72 ч. Ожидание не останавливает время, изменение приоритета требует
причины. Все записи времени хранятся в UTC, интерфейс показывает московское время.

## Повторная сборка документов

Нужны Python-пакеты из `requirements-docs.txt`, Chromium, LibreOffice и Times New
Roman. В текущей среде установленный шрифт хранится вне репозитория, а его SHA-256
проверен по подписанному пакету Debian `ttf-mscorefonts-installer`.

```bash
python tools/diagrams.py
python tools/render_diagrams.py
python tools/report4.py
python tools/report5.py
python tools/report6.py
python tools/finalize_reports.py
python tools/validate_deliverables.py
python tools/package_deliverables.py
```

Отчёт №6 строится по выполненным проверкам в `evidence`, поэтому после изменения
приложения сначала нужно повторить затронутые тесты. Сборка формирует настоящее
поле оглавления Word по стилям заголовков и заполняет его по фактической пагинации
PDF. Проверяются стабилизация номеров страниц, ссылки содержания и структура
документов. При изменении текста в Word оглавление можно обновить как обычное поле.
Титульные листы, структура разделов и оформление диаграмм приведены к предоставленным
образцам. В IDEF0 у каждой услуги четыре функции первого уровня, и каждая раскрыта
на отдельном листе; диаграммы содержат рамку, штамп и отдельные стрелки ICOM.
Список источников исключён из готовых отчётов.
В оглавлении кликабельна вся строка, включая номер страницы: в Word переход
выполняется через Ctrl + щелчок, в PDF обычным щелчком.

## Границы прототипа

Три модуля, роли, зависимости услуг и КЕ, история и сроки инцидентов реализованы.
Интеграции с vSphere, Zabbix и Veeam, финансовые кредиты, промышленная доступность,
нагрузочные испытания и автоматическое обнаружение циклов зависимостей не входят
в реализованный прототип. Инфраструктурные ресурсы в каталоге описывают предприятие,
а записи о восстановлении демонстрируют работу учётной системы.
